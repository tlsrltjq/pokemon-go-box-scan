일반 규칙으로 처리되는 메가 보스는 해당 보스 폼과 규칙을 검증해 일반 레이드 엔진에서 다룬다. 슈퍼 메가 등 별도 전투 메커니즘을 가진 콘텐츠는 자동으로 같은 규칙을 적용하지 않는다.

공개 서버, 회원가입, 멀티유저, 앱스토어 출시, 게임 계정 로그인, 비인가 게임 서버 조회, 메모리·패킷 읽기, 게임 자동 조작은 범위 밖이다. Mac이 꺼져 있으면 앱을 사용할 수 없다.

## 2. v1.1에서 바뀐 핵심 해석

1. 단순 지속 DPS 상위 6마리가 최종 목표가 아니다. 전투 조건별 예상 누적 피해로 파티와 출전 순서를 평가한다. 이론 DPS는 설명·디버깅 보조 지표다.
2. 맥스배틀은 후속 프로젝트가 아니라 이번 완성 범위다. 일반·그림자는 최대 6마리, 맥스는 최대 3마리의 별도 엔진을 사용한다.
3. 보스 공격·기절·교체·재입장 등은 총피해에 영향을 주므로 추천 모델에 필요하다. 생존 자체를 우선하는 별도 추천 모드를 만드는 것은 아니다.
4. 보유 스페셜 기술이 둘이면 각각을 주력으로 사용하는 정책을 비교한다. 기본 기능에 기술 혼합 최적화는 요구하지 않는다.
5. 레벨은 우선 역산해 확정한다. 후보가 남는 경우에만 미확정으로 처리한다.
6. HP를 현재 HP·최대 HP·체력 IV로 분리한다.
7. 외부 AI 관련 구현·비밀키 설정은 제거하고 Excel 내보내기를 제공한다.
8. 기본형·메가형 스캔은 같은 개체의 서로 다른 관측이다. 별개의 보유 개체로 중복 추천하지 않는다.

## 3. 권장 실행 구조

사용자가 채택한 추천 방향을 구현 가능한 구조로 구체화한 설계다. OCR 엔진과 런타임의 정확한 버전은 Mac 환경·샘플 검증 후 잠근다.

```text
iPhone 화면 녹화
  → Safari 영상 업로드
  → Mac FastAPI: 파일 저장 + 작업 등록
  → Python 워커 1개: 프레임 추출 / OCR / IV 판독 / 개체 구간 구분
  → 검토 화면: 원본·값·신뢰도·변경 비교
  → 개체별 승인 → SQLite 박스·이력
  → 모드별 전투 엔진 → 파티·예상 피해·가정
  → Excel 내보내기 (사용자가 파일을 직접 외부에 전달)
```

| 영역 | 설계 |
| --- | --- |
| 프론트 | React + TypeScript + Vite, 모바일 카드·Mac 표·원본 비교 |
| API | Python + FastAPI, 프론트 빌드 결과와 API를 같은 출처로 제공 |
| 의존성 | Python uv·잠금 파일, 프론트 잠금 파일, 런타임 버전 명시 |
| 영상 | FFmpeg/ffprobe + OpenCV, 회전·해상도·코덱·타임스탬프 확인 |
| OCR | 로컬 전용 어댑터. Apple Vision을 우선 실험하되 지원 언어·macOS 조건과 한국어 기술명 정확도를 실측 후 확정 |
| IV | 막대 영역 검출·채움 길이 분석, 0~15 정수 판정과 원본 근거 |
| DB | SQLite + 마이그레이션. 짧은 트랜잭션·외래키·경합 재시도 |
| 분석 작업 | 별도 단일 워커, DB에 작업 상태·진행률·오류·재시도 기록 |
| 원본 보관 | DB와 별도 로컬 데이터 폴더. UUID 기반 파일명·상대 경로 |
| AI 설명 | 사용하지 않음. 계산 결과에서 템플릿 기반으로 근거 문장 생성 |

API 요청 처리 중 영상 전체 분석을 기다리지 않는다. 업로드 성공 시 작업 ID를 반환하고 프론트에서 상태를 조회한다. 작업 상태는 `QUEUED/RUNNING/REVIEW_READY/FAILED/CANCELED`로 구분한다. 서버 재시작 시 중단 작업을 검출해 재시도 대상으로 표시하며 승인된 박스를 중복 생성하지 않는다.

초기에는 컨테이너·Redis·분산 큐 없이 Mac에서 직접 실행한다. 데스크톱 단독 실행은 loopback에 바인딩하고 iPhone 접근용 LAN 모드를 명시적으로 켠다. LAN 모드에는 허용 Host·Origin, 파일 크기 제한, 로컬 페어링 토큰 등 간단한 접근 통제를 둔다. 회원가입은 만들지 않는다. 공유기 포트 포워딩·자동 공개 배포는 하지 않는다.

일반 Safari 웹앱으로 먼저 제공한다. 서비스 워커·오프라인 PWA는 초기 완료 기준이 아니며, 구현하려면 iPhone이 신뢰하는 HTTPS 구성이 별도로 필요하다. iPhone에서 Mac의 HTTP IP 주소로 접속하는 것은 localhost 예외가 아니다.

## 4. 영상 수집과 승인

### 4.1 첫 녹화와 화면 유형

5~10마리의 `상단 → 기술 → 조사 → 다음 개체` 영상을 확보한다. 같은 종·같은 CP 개체, 별명 변경, 기술 2개, 그림자, 메가 전후, 맥스 개체를 점진적으로 추가한다. 전환 속도·해상도·배율·게임 언어를 기록하고 현재 화면에서 실제로 보이는 항목을 확인한다.

화면 유형은 `DETAIL_TOP/DETAIL_MOVES/APPRAISAL/POWER_UP/MEGA_DETAIL/MAX_DETAIL/TRANSITION/UNKNOWN`으로 분리한다. 안정된 프레임을 우선 추출하고 매 프레임 OCR은 하지 않는다. 가로 이동만으로 개체 변경을 단정하지 않으며 화면 내용과 시간 연속성을 함께 사용한다.

상단의 이름은 별명일 수 있다. 종·폼을 이름 문자열 하나만으로 확정하지 않는다. 표준 포켓몬·폼·기술 사전에 없는 문자열은 미확인으로 남긴다. 레거시 기술은 현재 습득 목록에 없다는 이유로 삭제하지 않는다.

### 4.2 필드 근거와 검토

모든 추출 필드는 `value`, `source_frame`, `source_region`, `observed_at`, `recognizer_version`, `confidence`, `verification_status`를 갖는다. confidence는 검증된 정확도 확률이라고 표시하지 않는다.

- 원본 크롭·OCR 원문·정규화 결과를 함께 보여준다.
- 값 충돌·낮은 신뢰도·개체 경계 불명확 시 자동 병합을 중단한다.
- 사용자는 필드 수정, 개체 구간 분리·합치기, 신규·기존 연결, 보류를 할 수 있다.
- 개체 단위 부분 승인을 지원한다. 다른 개체의 분석 실패가 승인 가능한 개체를 막지 않는다.
- 승인 요청은 멱등적으로 처리해 중복 클릭·재시도가 개체를 중복 생성하지 않도록 한다.
- 영상 업로드가 끝난 후 Safari를 닫아도 Mac 워커는 분석을 계속한다. 업로드 중단은 별도 실패로 표시한다.

## 5. HP·IV·레벨

### 5.1 용어

| 필드 | 의미 | 사용 |
| --- | --- | --- |
| `current_hp` | 현재 남은 체력. 예시 80/150에서 80 | 현재 관측 상태 표시 |
| `max_hp` | 완전히 회복했을 때 체력. 같은 예시에서 150 | 레벨 역산·생존 시간 계산 |
| `iv_stamina` | 조사 화면의 체력 개체값 0~15 | 능력치·레벨 역산 |
| `base_stamina` | 종·폼의 기준 체력 종족값 | 기준 데이터 |

추천 기본은 전투 시작 전 완전히 회복된 상태다. 이는 스탯 강화 가정이 아니다. 화면의 current_hp를 몰래 max_hp로 바꾸지 않고 계산 입력에 `start_hp_policy=FULL_HEALTH`를 기록한다. 현재 체력 그대로 출전하는 선택 기능은 후속이며, 기본 결과에 회복 전제를 표시한다.

### 5.2 조사 화면에서 IV 막대 읽기

조사 화면의 공격·방어·체력 막대를 각각 0~15의 정수로 읽는다. 막대는 5점씩 세 칸으로 나뉘므로 한 칸의 20%가 1점이다. 첫 칸만 가득 차면 5, 첫 칸과 둘째 칸의 40%가 차면 7, 세 칸이 모두 차면 15다.

1. 동일 개체의 조사 창이 보이는 구간을 찾고, 원본 영상의 시각 정보를 사용해 그 구간의 프레임을 촘촘히 읽는다. 브라우저에서 보여주는 1초 간격 프레임은 영상 검토용이다. 조사 창이 나타난 직후는 판독에서 제외한다.
2. 각 칸의 시작점과 끝점을 찾고, 유효 너비를 5등분한다. 칸 사이 구분선과 여백은 계산에서 제외한다. 검출된 칸 위치로 0~15의 기준 끝 위치 16개를 만든다. 6은 둘째 칸의 20%, 7은 둘째 칸의 40% 위치다.
3. 같은 조사 창의 연속 프레임에서 세 막대의 실제 끝 위치가 모두 일정 시간 안정된 구간을 확인한다. 기준 위치에 한 번 닿거나 잠깐 같은 숫자로 읽힌 것만으로는 애니메이션 종료를 판단하지 않는다. 창이 열린 뒤 기다릴 시간과 안정 구간의 최소 길이는 실제 iPhone 영상에서 측정해 정한다. 개체가 바뀌거나 창이 닫히면 판정을 초기화한다.
4. 안정된 구간의 채움 끝을 기준 위치와 대조해 IV 후보를 만든다. 0은 막대가 정상적으로 검출되었고 채워진 색이 없는 경우다. 안정 구간을 확보하지 못했거나 영상이 너무 짧으면 자동 후보를 비워 두고 원본 확인 또는 재촬영을 안내한다. 스크린샷 한 장만 받은 경우에도 사용자가 애니메이션이 끝난 화면인지 확인한 뒤 승인한다. 기존 기록은 승인 전까지 보존한다.
5. 합성 입력으로 기준 위치 16개와 애니메이션이 중간 값 또는 짧은 정지 구간을 지나는 사례를 검증한다. 실제 iPhone 녹화에서는 조사 창이 빨리 닫히는 경우, 개체가 바뀌는 경우, 빈 막대(0), 칸 끝(5·10·15), 인접한 값(6·7 등)을 확인한다. 판독에 사용한 프레임을 저장해 사용자가 결과를 확인할 수 있게 한다.

공식 도움말은 조사에서 공격·방어·체력을 개별 확인할 수 있다고 안내한다. 칸별 픽셀 판독과 오차 기준은 실제 iPhone 스크린샷 또는 녹화 프레임으로 검증한다. [Pokémon GO 공식 조사 안내](https://scopelyexplore.helpshift.com/hc/en/5-pokemon-go/faq/1120-appraising-your-pokemon/)

### 5.3 레벨 역산

현재 규칙 버전의 종족값·CPM·CP/HP 계산 규칙과 관측값을 대조해 허용된 레벨 후보를 열거한다. 일반 레벨과 베스트 파트너 활성 등에 따른 유효 전투 레벨을 구분한다.

1. 종·폼, 정확한 공격/방어/체력 IV, 현재 CP로 후보를 계산한다.
2. 관측한 최대 HP가 있으면 일치하지 않는 후보를 제거한다.
3. 다음 **1회** 강화에 필요한 별의모래·일반 사탕·XL사탕 비용과 대조한다.
4. 반짝반짝·그림자·정화 등의 비용 보정과 파트너·특수 폼 규칙을 적용한다.
5. 후보가 하나면 `RESOLVED_BY_CONSTRAINTS`, 여러 개면 `AMBIGUOUS`, 없으면 `CONFLICT`로 기록한다.
6. 사용자 승인 후 레벨을 박스에 확정하되 계산에 사용한 데이터 버전과 근거를 보존한다.

비용표는 레벨 구간에서 같은 값이 반복되므로 비용만으로 항상 유일하지 않다. CP·HP도 반올림/내림·최솟값·특수 규칙으로 후보가 남을 수 있다. 유일한 해가 생기면 정상적으로 추천에 사용하며, 처음부터 레벨 미상으로 제외하지 않는다.

`사탕 보유량`과 `강화 필요 사탕 수`는 별개다. 다회 강화 선택 창의 합산 비용을 1회 비용으로 해석하지 않는다. 강화 미리보기의 목표 CP도 현재 CP에 덮어쓰지 않는다. 레벨 역산을 위해 실제 강화를 요구하지 않는다.

별의모래/사탕이 없어 강화가 불가능하거나 강화 한도에 도달해 비용을 확인할 수 없어도 다른 증거로 유일하게 결정되면 허용한다. 단순 폼에서는 CP·IV만으로 결정될 수 있고, 추가 정보는 필요한 경우 수집한다. 최대 HP를 직접 관측하지 못해도 확정 레벨·IV·검증된 규칙으로 산출 가능하면 계산값이라는 출처를 붙인다.

## 6. 강화·기술 변경 후 기존 개체 갱신

### 6.1 권장: 기존 개체에서 재스캔 시작

1. 박스에서 해당 개체를 선택하고 `이 개체 다시 스캔`을 누른다.
2. 새 영상·프레임을 등록해 기존 UUID에 연결할 관측 후보를 만든다.
3. 전후 비교를 표시한다. 아래는 동작 설명용 합성 예시다.

| 항목 | 기존 | 새 관측 | 처리 |
| --- | --- | --- | --- |
| CP | 2500 | 2700 | 변경 후보 |
| 레벨 | L1 | L2 | 각각 역산한 근거 표시; 실제 수치 아님 |
| IV | 15/14/15 | 15/14/15 | 일치 근거 |
| 기술 | A/B | A/C | 별도 실제 변경 확인 |
| 촬영 시각 | 이전 | 이후 | 관측 시점 확인 |

4. 사용자가 `기존 개체 갱신 / 다른 개체로 신규 등록 / 보류` 중 선택한다.
5. 갱신 승인 시 UUID를 유지하고 revision을 증가시키며 이전 값·근거를 보존한다.
6. 새 관측의 미인식 항목은 기존 값을 null로 지우지 않는다. 기존 값의 확인 시각을 그대로 유지한다.
7. 해당 개체에 의존한 추천은 오래된 결과로 표시하고 재계산 가능하게 한다. 과거 결과는 당시 입력으로 재현 가능하다.

기존 개체에서 시작해도 동일 개체라는 증명이 되지는 않는다. 다른 포켓몬을 잘못 촬영했을 수 있으므로 종·폼·IV·맥스 속성·외형 등 일관성을 검사하고 충돌을 경고한다. 강화만 한 것으로 신고했는데 IV가 달라졌다면 오인식·다른 개체·다른 상태 변화를 확인한다.

### 6.2 일괄 재스캔

- `이름+CP` 완전 일치를 요구하지 않는다. 강화하면 CP가 달라지므로 기존 후보를 놓친다.
- 종·폼/진화 관계, IV, 그림자·정화·맥스 속성, 획득일 등 관측 가능한 비교적 안정된 정보를 사용한다.
- 별명·CP·HP·기술·레벨은 바뀔 수 있으므로 단독 동일성 키로 쓰지 않는다.
- 같은 종·같은 IV의 다른 개체가 존재할 수 있으므로 후보 점수는 동일성 확정이 아니다.
- 후보가 하나여도 수동 승인한다. 후보가 여럿이면 비교 화면을 제공한다.
- 오래된 영상은 최신 관측을 자동 대체하지 않는다. 업로드 시각과 실제 촬영 시각을 분리한다.

### 6.3 선택 사항: 별명에 관리 번호 붙이기

앱에서 개체를 등록한 뒤 `PK0042`처럼 문자와 일련번호를 조합한 관리 코드를 확인한다. 사용자는 구분이 필요한 개체의 게임 내 별명에 그 코드를 직접 입력할 수 있다. 게임은 별명 검색과 도감 번호 검색을 모두 지원하므로 숫자만 입력하는 혼동을 줄이기 위해 문자 접두사를 제안한다. 일반 별명을 쓰거나 코드 없이 등록하는 방식도 지원한다.

1. 앱은 관리 코드를 한 개체에만 연결하고, 해당 개체를 삭제한 뒤에도 같은 코드를 재할당하지 않는다. 내부 UUID, 관리 코드, 영상에서 관측한 별명을 각각 기록한다.
2. 재스캔에서 읽은 코드가 기존 코드와 정확히 일치하면 기존 개체를 첫 갱신 후보로 표시한다. 코드가 중복으로 보이거나 종·폼 등과 충돌하면 관련 기록을 보여주고 선택을 맡긴다. OCR이 읽지 못한 코드를 추측해 연결하지 않는다.
3. 예를 들어 `PK0042`의 CP가 2500에서 2700으로 바뀌면 전후를 표시한다. 사용자가 승인하면 같은 개체의 CP와 실제로 확인된 변경값을 갱신하고, 이전 기록을 이력에 남긴다.
4. 코드가 없거나 게임에서 별명을 바꾼 경우에는 박스에서 기존 개체를 골라 재스캔하거나, 일괄 스캔 검토에서 후보를 직접 선택한다. 변경된 별명은 승인 후 반영한다.

### 6.4 메가 전후와 기타 변경

기본형·메가형은 같은 UUID 아래 observation을 각각 저장하고 사용자 확인으로 연결한다. `observed_form`, `observed_cp`, `observed_at`, `active_until`, `base_form_id`를 구분한다. 기본형 CP와 메가형 CP를 서로 덮어쓰지 않는다.

메가 OFF는 **기본 폼으로 비교하는 계획 모드**다. 현재 메가 상태를 촬영했어도 그 폼의 CP를 기본 폼 능력치와 혼용하지 않는다. ON은 현재 활성 또는 현재 사용 가능이 확인된 전투 상태를 후보로 추가한다. 같은 UUID는 한 파티에 한 번만 들어간다.

과거에 메가형을 스캔했다는 사실만으로 지금 활성·재활성 가능하다고 판단하지 않는다. 만료·현재 에너지·재사용 상태를 확인하고 미확인은 검토 대상으로 둔다. 관측하지 않은 필드를 임의로 메가 전후에 복사하지 않는다.

실제 진화·정화·기술 변경도 변경 유형을 명시하고 사용자 승인 후 이력을 만든다. 지원되지 않는 상태 변환은 자동 추론하지 않고 수동 검토한다.

## 7. 전투 추천의 목적과 공통 계약

### 7.1 목표 함수

최종 목표는 **주어진 보스·전투 규칙·시간·행동 정책에서 내 파티가 주는 예상 누적 피해**를 최대화하는 것이다. 친구·팀 보너스는 제외한다. 내구도는 피해를 줄 수 있는 시간에 영향을 주는 입력이며 별도 안정성 점수를 최우선으로 사용하지 않는다.

일반·그림자 레이드의 평가 구간은 적용 시간 제한, 보스 처치, 허용된 재입장 종료 등 시나리오 종료 조건까지다. 맥스배틀은 별도의 전투 종료·시간·단계 규칙을 사용한다. 일반 레이드의 타이머를 맥스배틀에 복사하지 않는다.

결과에는 다음을 표시한다.

- 추천 개체·출전 순서·폼·사용할 기술 및 선정 근거
- 제한/평가 시간 안의 예상 누적 피해, 유효 전투 시간, 기절·재입장 횟수
- 보조 지표인 이론 지속 DPS와 실제 시나리오 기반 평균 DPS의 구분
- 모드, 난이도, 보스 기술 정책, 회복·회피·재입장 가정
- 불확실한 조건에 따른 결과 범위와 순위 변동
- 제외 개체와 사유, 계산 규칙·게임 데이터·박스 revision

보스가 먼저 쓰러지는 비교에서는 처치 시간 등을 보조 기준으로 사용한다. 여럿이 참여하는 콘텐츠에서 내 피해 추정만으로 전체 그룹 승리를 보장하지 않는다.

### 7.2 스페셜 기술 2개

사용자 의도는 **두 기술을 비교해 해당 보스에게 더 유리한 하나를 주력으로 쓰는 것**이다. 기술머신 사용이나 기술 혼합 최적화를 기본 요구로 만들지 않는다.

- 현재 보유 노말 기술 + 스페셜 1을 사용하는 전투를 평가한다.
- 동일 조건에서 현재 보유 노말 기술 + 스페셜 2를 사용하는 전투를 평가한다.
- 타입 상성, 자속, 위력, 에너지 필요량, 시전·피해 발생 시간과 남은 전투 시간을 반영한다.
- 해당 정책에서 총피해가 높은 기술을 선택해 결과에 표시한다.
- 약점 기술은 유력 후보지만 약점 타입만 보고 다른 보유 기술을 제거하지 않는다. 약점·비약점의 실제 결과가 다르면 이유를 설명한다.
- 사용할 수 있는 에너지가 모이면 선택한 스페셜을 사용하되 종료 전에 피해가 들어오지 않는 경우 등의 처리 규칙을 명시한다.

기본 탐색은 한 스페셜을 주력으로 쓰는 정책 범위 안에서의 최선이다. 두 기술 혼합까지 포함한 모든 행동의 수학적 전역 최적이라고 표현하지 않는다. 추가 메가 기술은 전투 중에만 생성되는 기술 후보로 분리하고 기본 보유 기술을 덮어쓰지 않는다.

### 7.3 후보·파티 탐색

추천 가능 여부는 개체 단일 플래그가 아니라 모드별로 평가한다. 일반 레이드 준비가 끝나도 맥스 기술 정보가 없으면 맥스 추천에는 부족할 수 있다.

동일 UUID 중복·메가 동시 활성·참가 자격 제약을 적용한다. 개별 DPS로 정렬만 해서 파티 최적화가 끝났다고 하지 않는다. 파티·출전 순서를 탐색하고 후보 축소 기준·탐색 예산·동점 정렬 기준을 버전으로 기록한다. 작은 합성 집합에서는 전수 탐색 결과와 대조한다. 큰 박스에서 근사 탐색을 사용하면 그 사실을 표시한다.

자격 있는 개체가 정원보다 적으면 가능한 수와 부족 이유를 반환한다. 같은 개체를 복제해 자리를 채우지 않는다. 계산 규칙이 없으면 0 피해로 위장하지 않고 `UNSUPPORTED_RULESET`을 반환한다.

## 8. 모드별 엔진과 계산 가정

### 8.1 일반 레이드

버전 관리된 이벤트 기반 계산으로 기술 시작·피해 발생·종료, 에너지 생성/소비, 보스 공격·피격 에너지, 기절, 다음 개체 출전, 전멸·재입장을 모델링한다. 피해량·상성·STAB·날씨·그림자 개체·폼 변경·파트너 유효 레벨을 검증된 규칙에서 읽는다.

보스 입력은 종·폼뿐 아니라 `mode + tier + ruleset_version`으로 구분한다. 보스 HP/방어/공격·허용 기술·시간 제한을 해당 규칙에 연결한다.

초기 기본 가정 제안:

- 전투 시작: 전원 회복, 에너지 0, 회피 없음.
- 보스 기술 미선택: 검증된 기술 조합별 시나리오를 계산하고 평균·최저·최고를 표시. 실제 확률을 모르면 균등 시나리오 평균임을 명시한다.
- 재입장: 완전히 회복된 같은 파티로 다시 참가하는 비교 모드를 제공하되 재입장 지연을 입력·표시한다. 지연 미측정 상태에서는 사용자가 설정한 시나리오 값이며 실제값이 아니다.
- 재입장 없이 최초 파티만 평가하는 결과도 구분한다. 재입장 조건이 없으면 시간 제한 전체를 공격했다고 가정하지 않는다.

수치 기본값은 실측·규칙 검증 후 정한다. 이 문서는 임의의 재입장 초 수를 게임 사실로 확정하지 않는다.

### 8.2 그림자 레이드

일반 엔진에 보스의 격앙·진정 상태와 적용 시점·공방 보정·정화 크리스탈 시나리오를 추가한다. 그림자 공격자 보정과 그림자 보스 상태는 별개다.

정화 크리스탈 사용·진정 시점을 알 수 없을 때 몰래 즉시 진정으로 계산하지 않는다. 미진정/사용자 지정 진정 조건 등의 시나리오를 비교한다. 보스 HP 비율에 의존한 전이는 참여자 전체 피해의 영향을 받으므로, 팀 보너스를 제외해도 전이 시나리오 입력은 필요하다. 다른 트레이너의 피해를 모를 경우 해당 가정을 표시한다.

지원 완료 조건은 단순 그림자 배지 표시가 아니라 상태 전이가 피해량·생존 시간·순위에 반영되고 검증되는 것이다. 필요한 정확한 수치·특정 이벤트 예외는 구현 시 검증한다.

### 8.3 맥스배틀

별도 엔진과 최대 3개체 파티를 사용한다. 참가 가능한 다이맥스·거다이맥스 개체, 실제 맥스 기술과 해금/레벨, 일반 단계·맥스 단계, 게이지·단계 전환, 교체·기절·종료 규칙을 처리한다.

일반 단계용 기술과 맥스 공격을 분리한다. 타입·기술 파생 규칙은 검증된 모드 데이터에서 결정한다. 일반 레이드 메가 토글은 맥스 모드에 적용하지 않으며 참가 자격이 없는 상태는 제외한다.

최대 피해 목적이라도 더 오래 공격하게 만드는 교체·자기 회복·가드가 유리할 수 있다. 실제 해금된 행동만 후보에 넣고 각 행동이 내 누적 피해에 미치는 결과로 비교한다. 팀 전용 힐러·탱커 우선순위나 타인에게 준 회복량을 별도 목표로 삼지 않는다.

다른 트레이너의 친구·메가 보너스는 제외하지만 공유 게이지·보스 타깃 등 전투 메커니즘까지 없다고 가정하지 않는다. 모르는 동료 행동은 0 기여 기준 또는 명시적 전환 시나리오로 표현한다. 기본 시나리오와 동료 기여 가정을 결과에 기록하며 특정 그룹 실전의 확정 예측으로 표시하지 않는다.

일반 레이드와 다른 시간 경과·격앙·종료 규칙을 검증해야 한다. 데이터가 없는 동안 임의의 일반 레이드 시간 제한으로 대체하지 않는다. 일반 DPS 순위만 출력한 상태는 맥스배틀 지원 완료가 아니다.

## 9. 기준 데이터와 버전

PoGo API를 첫 수치 공급원 후보로 사용하고 로컬 정규화 스냅샷으로 저장한다. 이는 Pokémon GO의 공식 계정 API가 아니며 최신성·정확성·재배포 조건을 별도 확인한다.

필수 데이터:

- 종·폼별 공격/방어/체력·타입, 한국어 이름·별칭 매핑
- PvE 기술 위력·시간·피해 발생 시점·에너지, 한국어 기술명 매핑
- 타입 상성·날씨·CPM·CP/HP 규칙
- `pokemon_powerup_requirements.json`의 1회 강화 비용 및 상태별 보정
- 메가 전투 폼·현재 가용성·추가 기술 적용 대상과 규칙
- 보스별 모드·등급·HP/능력치·기술·시간/종료 규칙
- 그림자 격앙/진정, 맥스 단계·기술·게이지·보스 행동 규칙

하나의 공급원이 전부 제공한다고 가정하지 않는다. 특히 맥스·그림자 전투 상세 수치는 별도 출처·검증 테이블이 필요하다. PvP 데이터를 PvE에 섞지 않는다. 한국어↔내부 ID 사전 출처와 폼별 매핑은 아직 검증 과제다.

수동 갱신 → 원본 해시 비교 → 변경 파일 다운로드 → 스키마·단위·참조 검증 → 임시 스냅샷 → 회귀 검증 → 활성 버전 전환 순서로 처리한다. 실패 시 이전 정상 버전을 유지한다. 다운로드 날짜와 원천 데이터 갱신 날짜를 구분한다.

원본 URL·출처·해시·가져온 시각·검증 상태를 기록한다. 다른 출처가 충돌하면 조용히 혼합하지 않는다. 과거 추천에 필요한 스냅샷은 유지하고 사용자 관측값은 기준 데이터 갱신으로 덮어쓰지 않는다.

## 11. 화면·API

내비게이션은 내 박스 / 스캔·검토 / 전투 추천 / 설정·내보내기다. 목록에서 검색·필터·정렬, 동일 종 비교, 마지막 확인 시각·미확인 필드를 제공한다. 기준 없는 범용 화력 정렬은 기본 제공하지 않는다.

전투 추천 입력은 모드·보스(폼/등급 포함)·날씨·모드별 옵션이다. 일반/그림자에는 메가 포함 토글을 둔다. 보스 기술·재입장·격앙/진정·맥스 시나리오는 고급 설정으로 숨길 수 있지만 적용된 기본 가정은 결과 상단에서 볼 수 있어야 한다.

```text
POST /api/scans                      영상 업로드 / 기존 개체 target UUID 선택
GET  /api/scans/{id}                 작업 상태
POST /api/scans/{id}/cancel          취소
POST /api/scans/{id}/retry           재시도
GET  /api/scans/{id}/items           검토 후보
POST /api/review-items/{id}/approve  신규/갱신/연결 개체별 승인
GET  /api/pokemon                    목록·필터
GET  /api/pokemon/{id}               상세·원본·상태
PATCH /api/pokemon/{id}              revision 확인 후 수동 수정
GET  /api/pokemon/{id}/revisions     이력·변경 비교
DELETE /api/pokemon/{id}             보유 목록에서 제거
GET  /api/battle-bosses              모드/폼/등급별 보스
POST /api/battles/recommend          모드별 추천
GET  /api/game-data/version         출처·활성 버전·지원 범위
POST /api/game-data/update          수동 기준 데이터 갱신
POST /api/exports/xlsx              Excel 내보내기
POST /api/backups                   백업 생성
POST /api/backups/restore           검증·미리보기 후 복원
```

API 오류는 미확인 입력, 지원하지 않는 규칙, 데이터 충돌, 외부 데이터 갱신 실패, 저장 공간 부족을 구분한다. revision 불일치 시 최신 값과 비교하도록 하며 여러 탭의 수정 내용을 덮어쓰지 않는다.

## 12. Excel·원본·백업

Excel `.xlsx` 내보내기는 이번 완성 범위다. 시트는 포켓몬 목록 / 기술 / 메가·맥스 / 추천 결과 / 메타데이터로 구성한다. UUID, 종·폼, CP, 최대 HP, IV, 확정/후보 레벨, 기술 ID·한국어 이름, 검증 상태·시각, 데이터 버전을 포함한다. 미확인 값을 0으로 채우지 않는다.

별명 등 사용자 텍스트는 수식으로 실행되지 않는 문자열로 내보낸다. 영상·프레임·개인 촬영 메타데이터는 기본 Excel에 포함하지 않는다. 외부 AI 이용은 사용자가 파일을 직접 선택해 수행하며 앱은 외부 AI 통신이나 자동 업로드를 하지 않는다. Excel 편집 결과 재가져오기는 이번 기본 범위에 포함하지 않는다.

원본은 자동 만료 삭제 없이 사용자가 정리한다. 용량과 사용 중인 근거를 보여주고 영상만 삭제/프레임까지 삭제를 구분한다. 원본을 지워도 승인된 박스·변경 이력·계산 입력은 유지하며 원본 삭제 사실을 표시한다.

완전 복원용 백업은 DB 일관성 스냅샷 + 스키마 버전 + 필요한 기준 데이터 + 매니페스트/해시로 구성하고 근거 프레임·영상은 선택 포함한다. Excel은 완전 백업을 대체하지 않는다. 복원 전 검사·미리보기·현재 DB 백업을 수행한다. 절대 로컬 경로에 의존하지 않는다.

## 13. 구현 순서와 완료 기준

단계는 개발 순서이며 일반·그림자·맥스 추천 모두 이번 전체 목표다.

1. **환경·하네스:** 별도 저장소, Mac 설치·실행 문서, 버전 잠금, 진단 명령, 합성 샘플·CI. Mac에서 clone 후 재현 확인.
2. **영상 PoC:** 실제 5~10개체로 OCR·IV·경계 인식·레벨 역산 검증. 원본 비교와 오류 수정 가능.
3. **박스:** DB·마이그레이션·개체별 승인·이력·강화 후 재스캔·메가 전후 연결·Excel·백업.
4. **일반 엔진:** 기본 피해량과 기술 정책을 검증한 뒤 시간·피격·기절·재입장·파티 탐색 연결.
5. **그림자 엔진:** 격앙/진정 시나리오와 상태 전이 검증.
6. **맥스 엔진:** 참가 자격·3개체·맥스 기술 레벨·일반/맥스 단계·공유 메커니즘 가정 검증.
7. **통합 검증:** 실제 20~30개체로 수집·갱신·추천·내보내기·복원과 Safari 동작 확인.

첫 저장소에는 README, 기준 기획서, AGENTS.md/동일 CLAUDE.md, 환경 예시, 잠금 파일, 진단·테스트 명령을 둔다. 실제 영상·DB·프레임·모델 캐시·비밀값은 Git에서 제외한다. 외부 기준 데이터 재배포는 조건 확인 후 결정한다. 프로젝트 코드 작업 규칙과 허브 규칙을 혼동하지 않는다.

| 영상 길이·크기·성능 목표 | 측정 필요 | 10개체 샘플 처리·수정 시간 측정 후 한도 설정 |
| 한국어 사전·맥스/그림자 세부 데이터 | 자료 검증 | 출처·단위·라이선스·지원 범위 확보 |
| 보스 기술·재입장 지연·진정·맥스 동료 기여 | 계산 시나리오 | 8장의 기본 가정을 구현·표시하고 실제값과 구분 |
| 파티 탐색 최적성 | 알고리즘 검증 | 작은 전수 탐색과 비교, 대형 박스 근사 범위 표시 |

팀 보너스를 제외한다는 선택만으로 보스 공격·공유 단계·진정 시점이 확정되지는 않는다. 모르는 조건은 시나리오로 표시하는 것이 현재 정책이며 실제 전투의 확정 최대 피해를 보장하지 않는다.

## 16. 출처·확인 범위

2026-11-11 공개 문서와 사용자 대화를 확인했다. 공식 도움말은 개념 확인 자료이며 모든 전투 수치·공식·시간을 완전히 제공하는 데이터셋은 아니다.

- [공식: 강화](https://niantic.helpshift.com/hc/en/6-pokemon-go/faq/2372-powering-up-pokemon/) — 강화에 따른 CP/HP 변화와 비용·다회 강화 UI.
- [공식: 포켓몬 상세 화면](https://niantic.helpshift.com/hc/en/6-pokemon-go/faq/2391-viewing-a-pokemon-summary/)에서 별명을 편집할 수 있다. [공식: 박스 검색](https://niantic.helpshift.com/hc/en/6-pokemon-go/faq/1486-searching-filtering-your-pokemon-inventory/)은 별명과 도감 번호 검색을 안내한다. 관리 코드 형식과 갱신 흐름은 이 프로젝트의 설계다.
- [PoGo API 제공자 문서](https://pogoapi.net/documentation/) — CPM·1회 강화 비용·종/폼·기술·해시 캐시. 강화 비용은 같은 값이 여러 레벨에서 반복되는 구조. 실제 비용 JSON 직접 열기는 이번 웹 도구에서 실패했으며 API 응답 검증 완료로 보지 않는다.
- [공식: 그림자 레이드](https://scopelyexplore.helpshift.com/hc/en/5-pokemon-go/faq/1187-what-are-shadow-raids/?hl=en) — 보스 격앙과 정화 크리스탈에 의한 진정.
- [공식: 메가진화](https://scopelyexplore.helpshift.com/hc/en/5-pokemon-go/faq/1197-what-is-mega-evolution/) — 일시적 폼 변경·특정 추가 기술·메가레벨 보정. 모든 종의 상세 규칙 확보를 뜻하지 않음.
- [Pokémon 공식: 맥스배틀 안내](https://www.pokemon.com/us/features/the-great-pokemon-go-guide-to-winning-max-battles-and-catching-gigantamax-pokemon) — 맥스 공격·가드·회복의 구분. 정밀 수치·종료 규칙은 추가 검증.
- [Pokémon GO 공식: 맥스 포켓몬](https://pokemongo.com/en/max-pokemon-battle) — 맥스배틀 기본 안내.
- [Apple Vision 텍스트 인식](https://developer.apple.com/documentation/vision/recognizing-text-in-images) — 로컬 OCR 후보; 현재 기기에서 언어·revision 지원 여부 확인 필요.
- [FastAPI Background Tasks](https://fastapi.tiangolo.com/tutorial/background-tasks/) — 무거운 계산의 별도 처리 고려.
- [uv 프로젝트 관리](https://docs.astral.sh/uv/guides/projects/) — 환경·잠금 파일.
- [MDN Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) — 보안 컨텍스트 제약.

v1.2 작성 시점에는 게임 화면 판독, Mac 실행, 전투 계산 정확도를 확인하지 않았다. 첫 구현의 실행 방법과 검증 범위는 [README](../README.md)에 기록한다.
